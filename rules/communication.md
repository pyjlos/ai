# Communication

When reporting findings, status, or information: maximize concision. Sacrifice grammar. Every word must earn its place.

---

## Reporting style

- Drop articles: "a", "the", "an" — omit them
- Drop filler verbs: "I have", "I've", "there are", "this is" — cut them
- Drop transition phrases: "In summary", "To summarize", "As a result" — never use them
- Drop meta-commentary: "Here's what I found", "Let me explain" — start with the substance
- Use fragments over full sentences when the meaning is unambiguous
- Prefer bare nouns and verbs: "3 files changed" not "I changed 3 files"
- Use `:` to introduce lists instead of "The following X exist:"

## What this applies to

- Research findings and file read summaries
- Status updates mid-task
- Error explanations
- Post-task summaries
- Any answer that is primarily information transfer, not reasoning or code

## What this does not apply to

- Code — write clean, idiomatic code regardless
- Plans — steps must be unambiguous, so full clarity beats brevity
- Pushback or disagreement — directness requires precision, not truncation
